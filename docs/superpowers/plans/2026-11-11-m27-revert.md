# M27 — Revert

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `2026-11-11-yars-roadmap-to-v1.md` first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** every workflow step can be taken back to the state before it, with a reason, from the page, the bulk bar and MCP.

**Architecture:** the workflow already has `reopen` (complete → verification, directors, no reason). This milestone adds `unreport` (reported → complete), makes both need a reason, and labels both "Revert". No new status, no schema change: the reason is stored as the text of the chat event, as Return's is.

**Spec:** `docs/open-decisions-2026-11-07.md` R4: "A Revert action takes Complete back to Verification and Reported back to Complete, with a reason, written to the history." K1: all actions reversible. Roadmap question 6: whoever may mark reported may revert it.

**Branch:** `pr/21-revert` from `pr/14-hygiene-ci`.

**Gate:** canvas board 3.5 (workflow bar) shows the Revert slot in Complete and in Reported and its reason form. Signed off by the user.

## Review focus

1. A reported finding already sent to Confluence or Jira must keep its remote page link through a revert, so the next send updates the same page (task 2 `TestUnreportKeepsRemoteLink`).
2. Reverting Reported must not ask for a new approval: the approval stays (task 2 `TestUnreportKeepsApproval`).
3. An empty or blank reason must be refused everywhere: page, bulk, MCP (tasks 1, 3, 4).
4. Older clients that call `reopen` without a reason get a refusal that says what to send (task 4).
5. The bulk reason dialog must name the right verb for each action (task 3).

# M28 — file splits and test names

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (one agent, in order: the tasks touch the same files). Read `2026-11-11-yars-roadmap-to-v1.md` first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the two largest files of the store are split by responsibility, and tests are named after what they test, not after the milestone that added them.

**Architecture:** pure moves inside the same packages. No signature, no behaviour and no test body changes. Each commit moves code between files and nothing else, so its diff is equal additions and deletions.

**Spec:** the 2026-11-11 analysis: `internal/store/store.go` (about 2,100 lines) and `internal/store/checks.go` (about 1,000 lines) are touched by every feature; milestone-named test files hide what is covered.

**Branch:** `pr/22-structure`, cut after M23–M27 are merged or stacked, so no open branch has to be rebased over the moves.

## Review focus

1. A move that also edits a line hides a behaviour change: every commit must pass `git diff --stat` with insertions equal to deletions per package, and `gofmt` must not have reflowed anything else (each task's check step).
2. The lock order comment must stay next to the locks (task 1: `locks.go`).
3. No test may be lost in a rename (task 3: the list of test names before and after must be equal).

Rule for each test function in them: it moves, unchanged, to the test file of the production file that holds the first non-helper function it calls or the route it requests (for example a test that posts to `/e/{eng}/export` goes to `internal/web/export_test.go`; one that calls `Store.MergeInto` goes to the test file beside `merge.go`). If that test file does not exist, create it with the production file's name plus `_test.go`. Helpers used by several moved tests go to the package's existing helper file (`server_test.go` in web, `store_test.go` in store, `mcp_test.go` in mcp).

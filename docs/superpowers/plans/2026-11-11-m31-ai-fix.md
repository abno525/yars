# M31 — AI fixes check comments

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `2026-11-11-yars-roadmap-to-v1.md` first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** one button on a finding lets the configured AI fix the problems the checks reported: it edits the finding and replies in each check's chat thread, and both are marked as done by AI.

**Architecture:** a new provider call `Runner.Fix` returns a section's corrected text. `Store.FixChecks` runs in the background like a check run: for each open check result it asks for a fix, accepts it only if it changed nothing outside the paragraph that held the quoted problem and the rule no longer fires, commits it as "AI for <user>", and replies in the result's thread. Then it starts a normal check run. The AI never changes state, never dismisses anything and runs only for someone who may edit the finding.

**Spec:** `docs/open-decisions-2026-11-07.md` "Anything else" (a button that deploys the AI agent to fix all issues) and R7: "the AI answers only YARS's automatically generated comments (check results). It makes the fix in the finding automatically and replies in the thread, and both the edit and the reply are marked as done by AI."

**Branch:** `pr/25-ai-fix` from the branch that holds M24 (Checks strip), M25 (AI usage) and M28.

**Gate:** canvas: the button's slot on the Checks strip, the strip while fixing, the AI mark on a chat reply and in History. Signed off by the user.

## Review focus

1. Finding text is written by other people and may contain instructions for the model: a fix that touches anything outside the problem's paragraph must be thrown away (task 2 `TestFixRejectsChangeOutsideParagraph`).
2. A "fix" that does not fix must not be committed (task 2 `TestFixRejectsWhenRuleStillFires`).
3. A fix must never land on content that changed while the AI was thinking (task 2 `TestFixRefusedWhenSectionChanged`).
4. Sign-offs given before a fix must not count for the fixed text (existing behaviour: they are bound to the content hash; `TestFixVoidsSignOffs`).
5. One finding, one run at a time: a second press, or Check pressed during a fix, must not start a second job (task 2 `TestFixAndCheckExcludeEachOther`).

The system prompt, exactly:

```
You fix one problem in one section of a penetration-test finding. Reply with JSON only: {"body":"the whole section with the problem fixed"}. Change only the paragraph that contains the quoted text, and as little of it as fixes the problem. Keep every other character of the section as it is, including Markdown, code blocks and line breaks. ```
```

The user message: `Problem: <v.Message>\nRule: <ruleText>\nQuoted text: <v.Quote>\n\nSection (<section>):\n<body>`. The call uses purpose `fix` for the usage record (M25), the rule id, a token limit of 8192 (the rule check keeps 1024), and `rn.AITimeout`. The reply is parsed as `{"body": string}`; anything else is the error `the AI's reply was not the expected JSON`. `Fix` does not cache.

### Task 2: `Store.FixChecks`

**Files:** create `internal/store/fix.go`, `internal/store/fix_test.go`; modify `internal/chat/chat.go` (`KindAI = "ai"` beside `KindCheck`), the file holding `startCheck` (`checks_run.go`): a fix marks the finding as busy in the same `running` map

**Interfaces produced:**

```go
package store
// Fixer is a Linter that can also fix (rules.Engine).
type Fixer interface {
	Fix(ctx context.Context, v rules.Violation, section, body string) (string, error)
}
// FixRow is the outcome for one check result.
type FixRow struct{ Rule, Target, Quote, Outcome string; Fixed bool }
// StartFix starts fixing the finding's open check results in the background
// as u. It returns at once; progress is announced as ChangeCheck. While a
// check or a fix of the finding runs, it returns ErrBusy.
func (s *Store) StartFix(engID, dir string, u config.User) error
var ErrBusy = errors.New("a check or a fix of this finding is running")
// FixRunning reports whether a fix of the finding runs now.
func (s *Store) FixRunning(engID, fid string) bool
// fixRun marks a fix in the running map.
const fixRun = -1
```

What `StartFix` does:
1. Refuse (`*workflow.Denied`) unless `workflow.CanEdit(u, meta)` and the engagement is not archived. Refuse `ErrInvalidValue` "no AI provider configured" when the linter is not a `Fixer` or its `AIConfigured()` (M23) is false.
2. The work list is the results of the latest check run that finished on the current content (`CheckStatus`: `HasRun`, not `Running`, not `Stale`), which are not notices, are not dismissed, have a `Thread`, a non-empty `Quote` and a target `section:<Name>`. An empty list returns `ErrInvalidValue` "nothing to fix: run Check first".
3. Mark the finding busy (`setRunning(key, fixRun, false)` under `checksMu`, refusing with `ErrBusy` when the key is taken; `startCheck` refuses the same way while a fix runs).
4. In a goroutine (counted in `checkWG`), for each result in order:
   1. Read the section's current body. Ask `Fix`. An error is the outcome `not fixed: <error>`.
   2. **Accept only if all hold.** (a) `finding.ValidateBody(new)` passes. (b) Split old and new on blank lines (`regexp.MustCompile("\n[ \t]*\n+")`): the paragraph counts are equal, and every paragraph of old that does not contain the quote (compared after collapsing whitespace) is byte-identical in new. (c) Lint the changed finding with `rules.Fast`; for a script or AI rule also run that one rule (`CheckWith` with `Hooks{Only: rule}`): no violation of this rule with this quote in this target remains. (d) Compared with the fast rules' violations before, the new text has no new error in this section. A failed condition is the outcome `not fixed: <which condition, in words>`.
   3. Write with `UpdateSection(eng, dir, section, new, BodyHash(old), gitrepo.Author{Name: "AI for " + u.Username, Email: u.GitAuthor().Email})`. The commit subject is then `F-001: edit <section>` by `AI for <user>`. `ErrConflict` is the outcome `not fixed: the section changed meanwhile`.
   4. Reply in the result's thread, in one transaction: `chat.Message{User: u.Username, Kind: chat.KindAI, Reply: <thread>, Text: "Fixed."}` or `Text: "Not fixed: <reason>."`. No domain event is emitted (no notifications).
   5. `s.notify(Change{…, Kind: ChangeCheck})` after each row.
5. Afterwards: clear the busy mark, audit `ai.fix` with `eng/fid` and `<fixed> fixed · <skipped> not fixed`, and call `StartCheck(engID, dir, u)` so the threads of fixed problems resolve.

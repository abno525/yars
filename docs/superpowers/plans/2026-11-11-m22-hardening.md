# M22 — server hardening

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `2026-11-11-yars-roadmap-to-v1.md` first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the defaults are safe for a tool that holds pentest findings: strict response headers, an HTTPS option, a clean stop, no git command that can hang forever.

**Architecture:** one middleware in `internal/web` sets the headers. To allow a strict script policy, the six inline `onclick` handlers and the one htmx trigger filter that evaluates code move into `app.js`, and htmx is told never to evaluate code. `cmdServe` moves to its own file and gains signal handling and TLS flags.

**Spec:** the 2026-11-11 analysis (no page headers, no `Secure` cookie, no graceful stop, git without timeouts); `docs/superpowers/deferred-minors.md` lines "Script timeout kills only the direct child", "expired entries are never purged", "the cookie MaxAge is set at login only".

**Branch:** `pr/16-hardening` from `pr/14-hygiene-ci` (independent of M21).

## Review focus

1. A page that still relies on an inline handler or on htmx evaluating code would silently stop working under the policy (task 1 test `TestNoInlineHandlersInTemplates`, and the browser check in task 2).
2. The findings list must still not refresh while rows are ticked (task 1 browser check).
3. A request in flight when the server is told to stop must complete (task 4 `TestServeStopsCleanly`).
4. A long clone or push must not be cut by the new git timeout (task 5: only `gitrepo.run` gets it, not `git http-backend`).
5. A script rule that starts a background process must not leave it running after the timeout (task 6).

### Task 2: response headers

**Files:** create `internal/web/secure.go`; modify `internal/web/server.go:310` (`Handler`), `internal/web/secure_test.go`

**Interfaces produced:**

```go
// pagePolicy is the Content-Security-Policy of every page.
const pagePolicy = "default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; " +
	"font-src 'self'; connect-src 'self'; object-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'"
// secureHeaders sets the security headers; hsts adds Strict-Transport-Security.
func secureHeaders(hsts bool, next http.Handler) http.Handler
```

`secureHeaders` sets, before calling `next`: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`, `Content-Security-Policy: <pagePolicy>`, and with `hsts` `Strict-Transport-Security: max-age=31536000`. A handler that sets its own `Content-Security-Policy` afterwards (attachments, `attach.go:120`) overwrites the header, which is intended. It wraps the handler in `Handler()`: `return gzipHandler(secureHeaders(s.HTTPS, http.NewCrossOriginProtection().Handler(s.firstRun(root))))`. `Server` gains the field `HTTPS bool` (set in task 3).

### Task 4: `cmd/yars/serve.go` and a clean stop

**Files:** create `cmd/yars/serve.go`, `cmd/yars/serve_test.go`; modify `cmd/yars/main.go` (remove `cmdServe` and `backfillTeams`, which move unchanged)

**Interfaces produced:**

```go
// serve runs the server until ctx is cancelled, then stops it: new
// connections are refused, requests in flight get stopGrace to finish, the
// background workers stop, running checks get stopGrace, the database closes.
func serve(ctx context.Context, ln net.Listener, hs *http.Server, srv *web.Server, st *store.Store, d *db.DB) error
const stopGrace = 30 * time.Second
```

`cmdServe` builds everything as today, then: `ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)`, `ln, err := net.Listen("tcp", *addr)`, `return serve(ctx, ln, hs, srv, st, d)`. `serve` runs `hs.Serve(ln)` (or `hs.ServeTLS`) in a goroutine; on `ctx.Done()` it calls `hs.Shutdown` with a `stopGrace` timeout, `srv.Close()`, waits for `st.WaitChecks()` in a goroutine for at most `stopGrace`, then `d.Close()`. It returns nil on a clean stop (`http.ErrServerClosed` is not an error). It logs `yars stopping` and `yars stopped`.

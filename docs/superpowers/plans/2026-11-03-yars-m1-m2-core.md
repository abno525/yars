# YARS Core (Milestones 1–2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go + htmx server that reads a git data repo of engagements/findings, shows them engagement-scoped in a sortable table, and lets logged-in users create findings and edit them section by section, each edit becoming a git commit authored by that user.

**Architecture:** Git is the only storage. `internal/finding` parses/serializes `finding.md` (YAML front matter + `##` sections). `internal/gitrepo` shells out to `git`. `internal/store` maps the repo layout to engagements/findings and performs writes+commits under a mutex. `internal/index` holds an in-memory table rebuilt whenever HEAD changes. `internal/auth` handles local accounts and sessions. `internal/web` serves `html/template` pages with htmx for partial updates.

**Tech Stack:** Go 1.27 stdlib (`net/http` pattern routing, `html/template`, `embed`), `gopkg.in/yaml.v3`, `github.com/yuin/goldmark`, `golang.org/x/crypto/bcrypt`, htmx 2.0.4 (vendored), `git` CLI.

**Spec:** `docs/superpowers/specs/2026-11-03-yars-design.md`

## Global Constraints
- Single binary `yars`; module path `yars`.
- Data repo layout exactly as spec: `.yars/config.yaml`, `.yars/users.yaml`, `engagements/<eng-id>/engagement.yaml`, `engagements/<eng-id>/findings/<F-NNN-slug>/finding.md`.
- Front matter fields: `id, title, status, severity, cvss, author, reviewers, retest` (retest optional, omitted when empty).
- Statuses: `draft|verification|complete|reported`; new findings start `draft`.
- Default sections (config `sections`): `Description, Location, Impact, Steps to Reproduce, Remediation, References`.
- Roles: `pentester|reviewer|director|admin`.
- Every write = exactly one git commit, author `<username> <username@yars.local>` unless `users.yaml` gives `email`; message format `F-001: edit Impact`, `F-001: create`, `engagement <id>: create`.
- A finding can only be created via a URL under `/e/{eng}/` — there is no global "new finding" route.
- No JS frameworks; htmx only. Body text ≥ 16px, section textareas ≥ 12 rows, full width.

## Review Focus
1. A `## Heading` inside a fenced code block in a section must not split the section — round-trip byte-stable.
2. Unknown sections or extra front-matter keys written by a local editor/AI must be preserved on web edits, not dropped.
3. Path parameters (`{eng}`, `{fid}`) containing `..`, `/` or not matching `^[A-Za-z0-9._-]+$` must 404, never touch files outside the repo.
4. A commit made outside the app (local `git commit` in the data repo) must appear in the table on next request without restart.
5. CRLF line endings in `finding.md` must parse identically to LF.

### Task 1: Finding file format

**Interfaces — Produces:**
```go
type Retest struct { Source string `yaml:"source"`; Result string `yaml:"result"` }
type Meta struct {
  ID, Title, Status, Severity, CVSS, Author string   // yaml: id,title,status,severity,cvss,author
  Reviewers []string `yaml:"reviewers"`
  Retest *Retest `yaml:"retest,omitempty"`
  Extra map[string]any `yaml:",inline"`             // preserves unknown keys
}
type Section struct { Name, Body string }           // Body excludes the "## Name" line

func (f *Finding) Bytes() []byte
func (f *Finding) Section(name string) (string, bool)
func (f *Finding) SetSection(name, body string)     // replaces, or appends if missing
```

### Task 9: CLI entrypoint

**Files:** Create `cmd/yars/main.go`

- `yars init <dir>` → `gitrepo.Init`, writes `.yars/config.yaml` (from `config.Default()`), empty `.yars/users.yaml`, `engagements/.gitkeep`; commit `init` as `yars <yars@yars.local>`.

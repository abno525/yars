# M26 — redacted images: the mark and Purge from history

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `2026-11-11-yars-roadmap-to-v1.md` first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** when an image was redacted after its original was committed, the page says so with a very subtle mark, and a director can remove the original from the engagement's git history.

**Architecture:** the server records each redaction of a committed image in a small table. The mark is drawn where the image is listed. Purge rewrites the one engagement repository so that only the current version of that file remains, under the engagement's lock, then drops the unreachable objects. The ids of the removed blobs are remembered so that a later push from an old clone cannot bring them back.

**Spec:** `docs/open-decisions-2026-11-07.md` D28, answer (b): keep the history, a very subtle warning (a small dot in the corner, the detail on hover), a director-only "Purge from history".

**Branch:** `pr/20-redaction` from the branch that holds M24 (the Attachments panel).

**Gate:** canvas: the dot on a thumbnail and on an Attachments row; the Purge confirm page. Signed off by the user.

## Review focus

1. A push from a clone made before the purge must not bring the original back (task 3 `TestPushOfPurgedBlobRefused`).
2. A push that is running when the purge starts must end as either fully before or fully after it (task 2: both hold the engagement lock; `TestPurgeWaitsForLock`).
3. The purge must not change any finding's text, approval or sign-off (task 2 `TestPurgeKeepsStateAndContent`).
4. A purge that fails half-way must leave the repository as it was (task 2 `TestPurgeFailureLeavesRepo`).
5. An image redacted in the browser before its first upload has no original on the server and must show no mark (task 1 `TestFirstUploadHasNoMark`).

### Task 2: `Store.PurgeFromHistory`

**Files:** create `internal/store/purge.go`, `internal/store/purge_test.go`; modify `internal/gitrepo/gitrepo.go`

**Interfaces produced:**

```go
package gitrepo
// BlobsOf lists the distinct blob ids path has had in the history of HEAD, newest first.
func (r *Repo) BlobsOf(path string) ([]string, error)
// DropOldBlobs rewrites every commit of the current branch so that path is
// absent wherever its content is not keep, then removes the unreachable
// objects. The work tree is not changed.
func (r *Repo) DropOldBlobs(path, keep string) error

package store
// PurgeFromHistory removes every earlier version of an attachment from the
// engagement's git history. Directors only; not on an archived engagement.
func (s *Store) PurgeFromHistory(engID, dir, name string, u config.User) error
```

`DropOldBlobs`, exactly:
1. `git filter-branch -f --index-filter <filter> -- HEAD` with the environment `FILTER_BRANCH_SQUELCH_WARNING=1`, `YARS_P=<path>`, `YARS_KEEP=<keep>`, where `<filter>` is the one shell line
   `test "$(git rev-parse -q --verify ":$YARS_P")" = "$YARS_KEEP" || git rm -q --cached --ignore-unmatch -- "$YARS_P"`.
2. `git update-ref -d refs/original/refs/heads/main` (the branch name from `CurrentBranch`).
3. `git reflog expire --expire=now --all`.
4. `git gc --prune=now --quiet`.

`PurgeFromHistory`, exactly:
1. Refuse unless `workflow.AtLeast(u, "director")` (`*workflow.Denied`, "only a director can purge an image from history"); refuse an archived engagement (`ErrArchived`); the name must pass the attachment name rule.
2. Take the engagement lock for everything below.
3. `path = findings/<dir>/attachments/<name>`. `blobs = BlobsOf(path)`; the first is the current one. With one blob only: mark purged and return (nothing to remove).
4. Remember `head0`. Call `DropOldBlobs(path, blobs[0])`. On an error: `git reset --hard <head0>` and return the error (the old commits are still there until `gc`, which runs last).
5. `s.Invalidate(engID)`; `MarkPurged(engID, fid, name, blobs[1:])`; audit `attachment.purge` with `engID/fid/name`; `s.SyncPointers()` (takes the main lock: engagement before main is the allowed order); `s.notify(Change{Eng, Fid, Kind: ChangeContent})`.

### Task 3: a push cannot bring a purged original back

**Files:** modify `internal/policy/policy.go` (`Checker`, `checkCommit` or `file`), `internal/policy/policy_test.go`, `docs/git.md`

Rules: `Checker` loads `c.DB.PurgedBlobs(c.Eng)` once per `Check` (a database error refuses the push: "server: …"). For every changed file of every pushed commit whose `ch.Blob` is in the map, the problem is:
`commit <short>: <path> brings back <name>, which was purged from this engagement's history; clone the engagement again and redo your change`.
A pre-purge clone's push is first refused as "the server has newer commits; pull, then push again"; after the pull its merge still carries the old commits, and this check then refuses it. `docs/git.md` gains the row for this refusal in its table of refusals, with the fix "clone again".

- [x] **Step 1: write the failing tests.** `TestPushOfPurgedBlobRefused`: clone, purge on the server, in the clone `git pull` (a merge of the two histories), push: refused with `was purged`. `TestPushAfterFreshCloneAccepted`: a new clone after the purge can push a text change.
- [x] **Step 2–4:** fail, implement, pass (`go test ./internal/policy ./cmd/yars`). **Step 5:** commit: `feat(push): a purged original cannot be pushed back`.

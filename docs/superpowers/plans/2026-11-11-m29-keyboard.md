# M29 — keyboard

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Read `2026-11-11-yars-roadmap-to-v1.md` and sections 1 and 6 of `2026-11-05-keyboard-shortcuts.md` (the control inventory and the focus fixes) first. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the keyboard model the user described: click or keys select a panel, keys act on the selected panel, workflow keys fire at once, and everything can be switched off.

**Architecture:** the templates declare what exists (`data-kpanel` on selectable panels, `data-nav` on list rows, `aria-keyshortcuts` on controls); one dispatcher in a new `static/keys.js` finds a rendered, enabled control for the key and clicks it. Rights stay on the server: a control that is not rendered has no shortcut. The existing `e` and Ctrl+S code moves from `app.js` into `keys.js`.

**Spec:** `docs/open-decisions-2026-11-07.md` K1–K10, R3, R5, R6 and roadmap question 5. This plan supersedes section 3 (key map) and section 10 of the 2026-11-05 plan.

**Branch:** `pr/23-keyboard` from the branch that holds M24, M27 and M28.

**Gate:** canvas: the selected-panel border (the user asked for "a slightly visible change to the border"), the `?` overlay, the Preferences row. Signed off, together with the single keys of roadmap question 5.

## The key map (final)

| Key | Where | What it does |
|---|---|---|
| click | a panel | selects it |
| `j` / `k` | finding, report, template pages | select the next / previous panel; with nothing selected, the first |
| ↓ / ↑ | same | the same, only while a panel is selected (otherwise the page scrolls) |
| `l` or → / `h` or ← | finding page | select the chat panel / go back to the last selected main panel (arrows only while a panel is selected) |
| Esc | anywhere | closes the topmost thing: dialog → open popover → reason or dismiss form → open editor (with the discard question) → clears the selection |
| `e` | selected panel | opens its editor; nothing selected: nothing |
| Ctrl+S | any form with a focused field | saves that form; never on the login, setup or set-password pages; in a save conflict it only moves focus to "Keep mine" |
| Enter | selected panel, no field focused | presses the panel's button if it has exactly one besides Comment and Edit; otherwise nothing |
| `c` | finding page | comment on the selected panel (General when none) |
| Ctrl+Enter | chat composer, reply, reason forms, reviewer picker | sends that form |
| Shift+S / O / A / P | finding page | Submit / Sign off / Approve / Mark reported, at once |
| Shift+R / W / U | finding page | Return / Withdraw / Revert: opens the reason form (they need a reason) |
| Shift+T | finding page | Take back, at once |
| Shift+C | finding page | Check |
| Shift+H | finding, template pages | History |
| `i` `f` `b` `n` | signed in | Inbox / findings list / team board / new finding (the last three inside an engagement) |
| `/` | any page | focus the page's search box; without one, open Go to |
| `?` | any page | the shortcut list |
| `j` / `k`, Enter | lists | move the row focus; open the row |
| `x` | lists with checkboxes | tick the focused row |
| Shift+click, Shift+Space | lists with checkboxes | tick the range from the last ticked row |
| Shift+S / A / P | inbox and board bulk bar, with rows ticked | bulk Submit / Approve / Mark reported, at once |
| Ctrl+S, Ctrl+Z | Redact dialog | Save / Undo |

Single keys and Shift+key never act while the event target is an input, textarea, select or contenteditable, during IME composition, on key repeat, while a modal dialog is open, or when shortcuts are off. Ctrl+S, Ctrl+Enter, Ctrl+K and Esc always work.

`keys.js` structure (function names are fixed; tests look for them):

```js
// yarsKeysOff: shortcuts are switched off for this account.
function yarsKeysOff() { return document.documentElement.getAttribute('data-keys') === 'off'; }
// yarsTyping: the key goes into a field.
function yarsTyping(t) { /* moved from app.js, unchanged */ }
// yarsKeyOf(evt): "Shift+A", "Control+S", "Control+Enter", "E", "/", "?", "Escape" …
// built from evt.key (never evt.code); letters uppercased; Meta counts as Control.
function yarsKeyOf(evt) { … }
// yarsFire(key, scope): the first rendered, enabled element in scope (default
// document) whose aria-keyshortcuts lists key is clicked; true when one was.
function yarsFire(key, scope) { … }
document.addEventListener('keydown', function (evt) { … });
```

Dispatcher order in the `keydown` handler:
1. `Control+S`: always `preventDefault`; unless `evt.repeat`, call `yarsSave()` (task 3). Stop.
2. `Control+Enter`: `var f = evt.target.closest && evt.target.closest('form'); if (f) { evt.preventDefault(); f.requestSubmit(); }`. Stop.
3. `Escape`: `yarsEscape()` (task 2). Stop.
4. If `yarsKeysOff()`, `evt.isComposing`, `evt.repeat`, `evt.altKey`, `evt.defaultPrevented`, `yarsTyping(evt.target)` or `document.querySelector('dialog[open]')`: stop. (Ctrl+K is handled in `app.js` already.)
5. Navigation keys (`j k h l`, arrows): task 2 and task 5.
6. Everything else: `if (yarsFire(yarsKeyOf(evt))) evt.preventDefault();`.

A visible element is one with `offsetParent !== null`; enabled is `!el.disabled`.

### Task 2: selection

**Files:** modify `internal/web/templates/workflow.html:2`, `retest.html` (the result panel), `details.html`, `assets.html`, `cvss.html`, `partials.html` (`panel`, `editor`), `checks.html`, `chat.html:2`, `finding.html` (`attachments_panel`), `internal/web/static/keys.js`, `internal/web/static/style.css`, `internal/web/keys_test.go`

Rules:
1. Each of those panel roots gets `data-kpanel`. The chat panel gets `data-kpanel="side"`.
2. `keys.js`: `yarsSel` holds the selected panel's id. `yarsSelect(el)` sets `data-sel` on it, removes it from the others, stores the id, and calls `scrollIntoView({block: 'nearest'})`. A `pointerdown` inside a `[data-kpanel]` selects it. After an htmx swap of a panel with the stored id, `data-sel` is put back (`htmx:afterSettle`).
3. `j`/`k`: the list is `document.querySelectorAll('[data-kpanel]:not([data-kpanel="side"])')` in document order; with nothing selected, `j` and `k` select the first. Arrow keys do the same only when something is selected. `l`/→ selects `[data-kpanel="side"]` and remembers where it came from; `h`/← returns there.
4. `yarsEscape()`, in order, stops at the first that applies: an open `dialog` (the browser closes it; do nothing); an open `details.pop` (close it, focus its summary); a visible `.wfpanel`, `.dismissrow` or `.bdlg` (click its Cancel); an open editor in the selected panel (click its `[data-guard-cancel]`, which asks before discarding); a focused field (`blur()`); a selection (clear it).
5. CSS: `[data-kpanel][data-sel] { outline: 1px solid var(--ink); outline-offset: -1px; }` (the value on the canvas wins). Outline only.

### Task 3: `e`, Ctrl+S, Enter, `c`

**Files:** modify `internal/web/static/keys.js`; templates: `details.html`, `assets.html`, `cvss.html` (Save buttons get `aria-keyshortcuts="Control+S"`, Edit buttons `aria-keyshortcuts="E"`; Comment and Edit buttons get `data-kskip`), `login.html`, `setup.html`, `password.html` (their forms get `data-nosave`), `internal/web/keys_test.go`

Rules:
1. `yarsEdit()`: only the selected panel. If it is editing, focus its first field; else click its `button[aria-keyshortcuts~="E"]:not(:disabled)`. Nothing selected: return false. (The old fallback to the first text section is removed.)
2. `yarsSave()`: `var form = document.activeElement && document.activeElement.closest('form')`. No form, or `form.hasAttribute('data-nosave')`: nothing. A `.conflict` editor: focus its "Keep mine" button, nothing else. Else the button is `form.querySelector('[aria-keyshortcuts~="Control+S"]')` or, without one, the form's first `button:not([type=button])`; if it is disabled, nothing; else `form.requestSubmit(button)`. In the Redact dialog (the one case with a dialog open) Ctrl+S clicks `[data-redact-save]` and Ctrl+Z clicks `[data-redact-undo]`.
3. Enter with a selected panel and no field focused: `var b = panel.querySelectorAll('button:not(:disabled):not([data-kskip]), a.btn:not([data-kskip])')`; exactly one: click it; else nothing.
4. `c`: `yarsComment(<the selected panel's section name>)`; the name is the panel's `data-comment` button value, or `''` (General) when there is none or nothing is selected.
5. Focus after a save or cancel returns to the panel (the existing `yarsFocusAfter` logic moves along unchanged).

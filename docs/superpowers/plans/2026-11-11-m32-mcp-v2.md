**Goal:** an AI assistant can do through MCP what a person does on the daily pages, with one answer shape, clear error codes, and strict handling of malformed requests.

## What v1 has (the proposal to sign off)

**Answer shape.** Every tool's text is one JSON object. Success: `{"ok": true, …}`. A list: `{"ok": true, "items": […], "next": "<cursor or empty>"}`. A refusal: the MCP result has `isError: true` and the text `{"ok": false, "code": "<code>", "message": "<what to do>"}`.

**Error codes.** `not_found`, `not_allowed` (rights, token scope, workflow rule), `conflict` (changed since read), `invalid` (bad argument or value), `archived`, `busy` (a check or fix runs), `no_database` (a server-only tool on a local clone).

**Paging.** List tools take `limit` (default 50, at most 200) and `cursor` (the `next` of the previous answer; an offset as text).

**Tools.** Existing ones keep their names. Changes and additions:

| Tool | New or changed | What |
|---|---|---|
| `whoami` | new | username, role, admin flag, the token's scopes and engagements |
| `get_config` | new | sections, details rows, severities, CVSS version and standard values, statuses, transition actions |
| `list_team` | new | the engagement's members with roles |
| `list_findings` | changed | paged; `q` (the search of M23); an unknown status or severity is `invalid` with the valid values |
| `read_finding` | changed | each section has `body` as well as `base`; `allowed_actions` lists every transition with `enabled` and `reason`; `violations` unchanged |
| `read_chat` | new | the finding's whole timeline, paged, oldest first: threads with replies, and workflow events |
| `list_history` | new | the finding's versions: commit, author, time, the parts that changed |
| `list_attachments` | new | name, size, type, whether an earlier version is in history |
| `read_template` | new | a template's Markdown by slug |
| `transition` | changed | `revert`, `unreport` (M27) |
| `fix_checks` | new | starts the AI fix (M31); scope `checks` |
| `mark_notifications_read` | new | by ids, or all |
| `list_notifications` | changed | paged |

Not in v1 (noted for later): engagement create and settings, export, attachment upload, the team board, templates editing, a REST API.

## Review focus

### Task 1: strict requests (R2 items 1 and 2)

**Files:** modify `internal/mcp/http.go:40`, `internal/mcp/mcp.go:40-42,81-88`, `internal/mcp/mcp_test.go`, `docs/mcp.md`

Rules:
1. HTTP: the scheme word of `Authorization` is matched without regard to case (`bearer`, `Bearer`, `BEARER`), then one or more spaces, then the token.
2. `protocols` becomes `[]string{"2025-06-18", "2024-11-05"}` (2025-03-26 is no longer advertised: it requires request batches, which are not supported).
3. `Handle`, before the method switch: a body that is a JSON array answers `-32600` "batches are not supported"; `jsonrpc` other than `"2.0"` answers `-32600` "jsonrpc must be 2.0"; an `id` that is the JSON value `null` answers `-32600` "id must not be null" (a request without an `id` is still a notification and gets no answer).
4. `ServeStdio`: a line longer than the scanner's limit answers `-32700` and the session goes on (use a `bufio.Reader` and skip the rest of the line instead of ending on `bufio.ErrTooLong`).

### Task 3: one answer shape

**Files:** create `internal/mcp/envelope.go`, `internal/mcp/envelope_test.go`; modify `internal/mcp/mcp.go:125-138`, `internal/mcp/tools.go` (`explain`, every tool's return)
